# 完整工作台公网访问

入口：<https://workbench.wushi-api.com>。同一个域名已提供**免登录的真实内容访客版**，支持文字、数据、案例图片和视频预览，以及**账号密码登录后的完整工作台**。2026-10-16 已完成入口切换和未登录公网验收：打开页面无需 Cloudflare 账号或工作台密码，业务操作仍需登录。工作台账号可在本机「设置 → 公网账号」自行设置。

公网连接使用独立的 Cloudflare Tunnel，已设置为当前 Windows 用户登录后自动启动，Windows 每分钟检查并恢复已退出的公网管理进程。访问路径为：公网 HTTPS 地址 → 本机访问代理（127.0.0.1:8768）；未登录时读取私有目录中的访客快照，仅对白名单内的图片和视频预览转发到原工作台（127.0.0.1:8767），账号登录后才开放完整接口。电脑需开机联网；完整操作、访客媒体预览和访客数据更新需要本机工作台保持运行。

## 首次配置

### 工作台账号密码登录

支持工作台自己的账号密码，隧道仍使用 Cloudflare，访客和工作台账号用户都无需拥有 Cloudflare 账号。在本机工作台打开「设置 → 公网账号」，填写账号、密码和确认密码并保存。密码至少 12 个字符；不会保存明文，也不会进入项目目录。账号只能从运行工作台的电脑上的本机页面设置和重置，公网代理始终拒绝账号管理接口。

保存时在私有运行目录写入 `account.json`，并将 `config.json` 的 `authMode` 设为 `password`，通过指定实例的 `reload.request` 通知公网管理进程重载。未设置 `authMode` 时仍使用原来的 Cloudflare Access 登录。账号密码模式不依赖 Access 团队、AUD 或邮箱字段；这些旧配置会保留，方便回退。先部署并验证新版管理程序，再填写账号。

启用同域名访客版时，在现有私有配置中加入 `"authMode": "password"` 和 `"guestEnabled": true`，保留其他配置。`guestEnabled` 必须是布尔值，且只能与密码模式一起使用。即使尚未创建 `account.json`，访客仍可浏览已准备好的快照；完整接口和操作保持锁定。之后由用户在本机自行设置账号密码，登录后即可使用完整功能，不需要为了开放访客版而预设账号。

首次切换按以下顺序进行：

1. 保持原 Cloudflare Access 策略，先部署并启动支持访客版的快照生成程序和访问代理，确认私有访客快照已就绪。
2. 从本机验证代理已使用密码加访客模式：未登录根页面显示真实只读内容，白名单内的案例图片可查看、视频可播放和拖动进度；除登录相关入口外，访客白名单以外的接口和媒体、全部业务写请求、导入导出和完整数据下载均被拒绝；未设置账号时不能登录完整工作台。已设置账号时再验证登录与退出。
3. 通过上述检查后，仅调整**此工作台域名对应的** Cloudflare Access 策略，让未登录请求能够到达工作台代理，由代理区分访客和已登录账号。保留应用原配置以便回退，不改动其他应用的访问规则。
4. 用新的未登录浏览器会话进行公网验收，确认同域名访客版可打开、受限接口仍被拒绝，再记录部署已确认状态。私有 `deployment.json` 中的 `auth_method: "password_with_guest"` 仅在验收成功后填写；本机设置页据此显示公网已就绪，不能用这个标记代替验证。

回退时先恢复此域名的原 Cloudflare Access 策略，使外层重新要求原账号验证；随后将本机 `authMode` 改回 `cloudflare`，并将 `guestEnabled` 设为 `false`（或移除该字段），重启本工作台公网连接。确认 Access 签名和邮箱校验生效后，移除或更新私有部署记录中的访客就绪标记。这个顺序可避免切换期间把完整工作台直接开放。

密码使用带随机盐的 scrypt（N=32768、r=8、p=3）。登录会话使用随机、不透明的 Secure/HttpOnly Cookie，最多有效 24 小时，闲置 2 小时失效。退出登录、修改账号密码、代理重启都会要求重新登录。登录校验采用本机异步计算并限制尝试频率，正常操作不用等待第三方身份服务。未开启访客版时，账号文件缺失会阻止密码模式启动；开启访客版时，只有尚未设置账号的情形允许继续只读浏览，已有账号文件损坏仍会拒绝启动。修改账号密码会撤销旧会话，访客只读权限不随账号变更。

### 访客内容与快照更新

访客看到的是本机业务资料生成的真实文字和数据，能够浏览页面、搜索、切换栏目、查看已公开详情，以及预览已公开案例绑定的真实图片和视频。视频支持播放和拖动进度；图片包括视频封面、表现数据截图和画面缩略图。编辑、保存、删除、生成、导入、导出、工作台下载入口、运行 AI、剪辑和其它业务操作均不提供。音频和白名单外的附件保持受限，访问原媒体地址也不会绕过登录。完整工作台的凭据、令牌、本机路径和私有管理信息不进入访客快照。

媒体预览使用独立的 `/guest-media/{案例编号}/{媒体类型}` 入口，代理按私有快照中的 `media-index.json` 精确核对案例、事件版本和媒体类型。仅允许 `video`、`thumbnail`、`screenshot`、`contact_sheet`；每次转发固定到已公开的事件，不跟随本机后来修改的当前版本。只接受 GET/HEAD，拒绝下载参数、未知或重复参数以及白名单外资源；白名单缺失或损坏时停止放行。视频通过流式单段 Range 响应传输，支持进度拖动，无需先把整段视频读入代理内存。代理过滤 Cookie、凭据和私有响应头，并将上游错误统一处理，避免带出本机路径。

工作台的导出接口和下载入口对访客关闭，但浏览器播放视频、显示图片本身需要接收媒体字节，因此无法绝对阻止访问者通过浏览器自身保存已经可查看的媒体。

访客目录固定为 `runtime_root/remote-access/guest/site`。独立的 `guest_snapshot.py` 进程默认每 30 秒检查本机内容变化，有变化时通过本机只读接口生成并核对新快照，再替换已发布版本；生成耗时会叠加到检查间隔，不能视作实时同步。生成失败或本机服务暂时不可用时保留上一次有效快照；尚无有效快照时显示正在准备，不能转而读取完整工作台。快照和它的状态、日志都留在这个私有运行目录体系内，不发布到旧 Pages 网站。

访客页面和只读数据接口仅来自固定快照目录，媒体预览仅转发前述精确白名单内的请求，不把访客请求任意转发给本机服务。前端会收起操作入口，代理仍独立拒绝写入和未公开资源。快照资源按版本在代理中缓存，更新后切换到新版本；页面与数据保持 `private, no-store`，访客脚本和样式按实际内容哈希生成版本地址，匹配版本的资源可在浏览器私有缓存中长期复用，普通或旧版本地址逐次校验 ETag。文字响应按浏览器支持进行 gzip 压缩，并带 `Vary: Cookie, Accept-Encoding`，避免登录状态与压缩格式混用。图片可使用私有缓存重验证，每次仍先核对媒体白名单；视频继续使用原有流式 Range 传输。页面提供账号登录入口；登录后同一域名使用完整工作台，退出后回到访客浏览。

### 保留 Cloudflare Access 登录

需要保留原登录方式或执行回退时，使用独立的命名隧道，将指定公网域名连接到 `http://127.0.0.1:8768`。为完整域名全部路径建立 Access 应用，仅允许指定邮箱验证登录，关闭该应用的 Bypass 或 Everyone 规则。代理逐次验证 Access 签名、团队域名、应用 AUD、有效期和允许邮箱。这里使用单独隧道，不修改其他应用已有的 cloudflared 连接。

私有目录是工作台合并后的配置（`config.local.json` 优先）中 `runtime_root` 下的 `remote-access`，不在部署目录内。在其中保存 `config.json`：

```json
{
  "hostname": "workbench.example.com",
  "teamDomain": "https://your-team.cloudflareaccess.com",
  "audience": "填写该 Access 应用的 64 位十六进制 AUD",
  "allowedEmails": ["your-email@example.com"],
  "nodePath": "C:/Program Files/nodejs/node.exe",
  "cloudflaredPath": "C:/Users/YourName/.antigravity_tools/bin/cloudflared.exe",
  "httpsProxy": "http://127.0.0.1:7897"
}
```

将这个独立隧道的令牌单独写入同目录 `tunnel-token.txt`，只保存令牌内容，不加入命令行或代码。`httpsProxy` 可省略；填写时仅用于代理进程通过本地网络代理读取 Access 公钥，不改变系统代理。私有目录应仅允许当前 Windows 用户及系统访问，勿加入 Git 或上传到网站。

## 启动与管理

在工作台目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/manage_remote.ps1 -Action Start
powershell -ExecutionPolicy Bypass -File deployment/manage_remote.ps1 -Action Status
```

`Install` 注册当前用户的 `CaseWorkbenchRemoteAccess` 计划任务，登录启动、每分钟重试，并替换旧的 Startup 快捷方式；注册失败时保留原启动项。`Stop` 先禁用自动恢复，再停止本工作台的公网代理、独立隧道和已启用的访客快照进程，直到 `Start` 或 `Install` 重新启用。`Uninstall` 同时删除计划任务和旧启动项。停止时根据本次管理进程的实例与子进程句柄退出，不按程序名批量关闭 cloudflared。它不关闭原工作台，也不删除 Cloudflare 配置。

管理进程会在代理或隧道退出后退避重试；开启访客版时也负责独立快照进程的启动、停止与恢复。Windows 管理进程退出时会同时回收它拥有的子进程；计划任务会在下一次分钟触发时重新启动，进程仍存活但卡住的情形需要另行诊断。状态文件暂时写入失败不会中断健康连接。状态和轮换日志保存在私有目录内；日志记录启动、退出原因及异常类型，不记录令牌、请求或子进程原始输出。`children_running` 只表示本模式需要的子进程正在运行，不表示快照已完成或公网验收已通过。缺少配置或令牌时拒绝启动。手动修改私有配置后需先 Stop 再 Start；本机设置页保存账号会自行发出指定实例的重载请求。

公网代理复用少量本机 HTTP 连接，降低交互时等待开销。使用 Cloudflare Access 模式时，会在启动和公钥临近到期时提前获取 Access 公钥；每个请求仍验证签名及授权，过期公钥不可用时拒绝访问。密码模式使用本机会话校验，访客读取已生成的快照，正常浏览无需等待第三方身份服务。本机服务启用 `TCP_NODELAY`，避免复用连接上的小响应延迟。修改代理或管理程序后需重启公网连接；修改本机服务后需通过工作台的安全重启接口加载。

2026-10-21 公网加载优化：登录后的脚本、样式和图标也保留本机提供的私有资源缓存策略，页面、业务接口、下载和错误响应继续禁止存储。访客资源的有效版本必须与当前文件内容匹配，内容变更自动更新地址，旧地址不能把新内容长期缓存为旧版本。访客压缩发生在本机代理中，减少穿过隧道的数据量；重复打开工作台时，未变化的版本资源无需再次传输。以上优化通过重载公网连接生效，无需中断本机正在执行的 AI 协作或剪辑任务。

本次验收：同组 64 个访客脚本与样式经过本机代理传输的正文总量由 1,940,996 字节降至 547,727 字节，减少 71.8%。公网 Chrome 独立会话首次进入案例库约 7.25 秒，同一会话再次打开约 2.58 秒，第二次全部 64 个资源由浏览器缓存复用，资源网络传输为 0；两次均正常显示 50 张案例卡片且无页面脚本错误。这是当前网络条件下的首次与重复访问实测，不是优化前后的整页耗时对比。另已核对公网图片重验证返回 304、视频片段请求返回 206，未登录的完整业务接口及本机账号管理接口仍分别拒绝为 401 和 403。本次未重启本机主服务，正在运行的 AI 剪辑继续执行。

同日继续优化首次打开：访客脚本保持逐文件的独立执行语义，并按原顺序合并传输；样式按原层叠顺序合并。两个最早执行的只读启动脚本安全内联到页面，移除阻塞解析的额外下载，外部程序资源从 64 个减少到 2 个。案例状态在页面头部开始预取，与资源下载并行；首次普通读取复用同一个请求，后续刷新保持重新读取，自定义请求、导航变化、超时或失败均回到原有读取流程。生成资源只来自已经过隐私检查的源文件，继续按最终内容哈希缓存；业务数据和页面仍禁止缓存。本次通过重载独立公网连接生效，本机后台任务继续运行。

首次打开验收：同一电脑和网络分别进行三次全新 Chrome 会话、无资源缓存的公网案例库测试。优化前为 7.104、6.235、5.026 秒（中位 6.235 秒），优化后为 5.151、3.273、3.164 秒（中位 3.273 秒），中位耗时减少 47.5%。优化后三次均只下载 2 个外部程序资源，案例状态请求早于 DOMContentLoaded，正常显示 50 张卡片且无脚本错误；再次打开约 2.014 秒，两个资源包均复用缓存，资源网络传输为 0。这是本次网络条件下的浏览器实测，耗时会随网络变化。构建、脚本执行顺序、预取失败回退、完整页面导航与既有权限检查均通过相应回归验证。

## 使用范围

远程登录后操作的是这台电脑上的完整工作台，保存和删除会直接作用于本机数据。下载文件会保存到访问者设备；打开文件夹、目录选择和达芬奇操作发生在工作台电脑上。

停服和 Claude 账号授权只能在本机完成；「重启工作台」在公网页面上也能点，有任务在运行时工作台照样会拒绝重启。

Cloudflare Free/Pro [单次上传通常上限 100 MB](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/)，可能低于本机支持的视频与总数据包大小；大文件仍需在本机导入。完整备份、导出等耗时操作还受[公网请求超时](https://developers.cloudflare.com/fundamentals/reference/connection-limits/)影响。此连接不将本机数据迁移到 Cloudflare R2，也不替代本机备份。
