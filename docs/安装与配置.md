# 安装与配置：从零打开案例工作台

本教程按 Windows PowerShell 编写，Python 3.12 为当前使用基线。项目中的桌面启动器、打开本地文件、达芬奇连接、字体和部分授权适配以 Windows 为主；其他系统尚未作为完整工作流程验证。

## 1. 准备环境

需要：Windows 电脑、浏览器、Git、Python 3.12（64 位）。刚接触命令行时，可以在开始菜单搜索 **PowerShell** 并打开。

逐行检查：

```powershell
git --version
py -3.12 --version
```

两行都显示版本号再继续。如果提示“无法识别”，先安装对应软件，重新打开 PowerShell；安装 Python 时启用 Python Launcher。没有 `py` 但已经有正确的 Python 3.12 时，可把下文创建环境的 `py -3.12` 换成 `python`。

## 2. 下载代码并安装依赖

下面把项目放到用户目录。也可以先切换到自己用于存放项目的文件夹。

```powershell
Set-Location $env:USERPROFILE
git clone https://github.com/w393312401-afk/case-workbench.git
Set-Location case-workbench
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`.venv` 是这个项目专用的 Python 环境。后面的命令始终使用其中的 Python，避免依赖装到其他环境。不需要执行激活脚本，也不需要更改 PowerShell 的脚本执行策略。

基础依赖为 Pillow、NumPy、OpenCV 和 openpyxl，分别用于图片处理、图像计算与 Excel 表格。即使暂时只用评论功能，也应安装完整的基础依赖，因为应用启动时会加载对应模块。

如果不用 Git，也可在仓库页面点 **Code → Download ZIP**，解压后在包含 `server.py` 的文件夹打开 PowerShell，再从创建 `.venv` 的命令开始。ZIP 更新需要自行保留个人配置与数据；Git 更方便后续更新。

## 3. 第一次启动

```powershell
.\.venv\Scripts\python.exe server.py
```

看到下面这行说明服务已开始监听：

```text
Case workbench: http://127.0.0.1:8767
```

在同一台电脑的浏览器打开 `http://127.0.0.1:8767`。这就是自己的工作台地址。终端要保持打开；停止时回到终端按 `Ctrl+C`。

首次启动按以下顺序验收：

1. 浏览器能打开页面，侧栏能切换「案例库」「用户声音」「设置」。
2. 新安装的数据列表为空，没有原作者的案例、评论、销售数据。
3. 「设置 → 本地文件」能读到本机路径。
4. 「设置 → 模型与连接」即使显示 AI 未连接，基础界面仍可使用。

空库与 AI 未连接并不代表安装失败。先把基础界面跑通，再配置需要的功能。

默认服务地址只供本机访问。公网部署是另一个流程，见 `deployment/` 的说明；发布应用源码并不自动发布自己电脑里的业务资料。

## 4. 配置自己的数据位置

`config.json` 是仓库中的通用默认配置。个性化设置放到 `config.local.json`，避免更新源码时覆盖，也避免随 Git 提交。

```powershell
Copy-Item config.json config.local.json
notepad config.local.json
```

已有 `config.local.json` 时直接打开编辑，不要再用复制命令覆盖它。

默认配置的主要字段：

| 字段 | 用途 | 默认值 |
| --- | --- | --- |
| `skill_root` | 正式案例存储根目录；历史上也用于定位个人技能资料 | `.local/case-library` |
| `runtime_root` | 评论、方向、创作、销售、制作等运行资料 | `.local/runtime` |
| `port` | 浏览器访问端口 | `8767` |
| `performance_sources` | 要扫描的销售报表文件夹列表 | `[]`，没有额外目录 |

相对路径按项目文件夹解析，不按打开 PowerShell 时所在的位置解析。**`skill_root` 与 `runtime_root` 必须是两个独立目录，不能相同，也不能一个包含另一个。** 默认二者是 `.local` 下的并列目录。自定义 JSON 里的 Windows 路径推荐用正斜杠，例如 `D:/WorkbenchData/runtime`；若使用反斜杠，每个都要写成 `\\`。

例如，将业务资料独立放到 D 盘：

```json
{
  "skill_root": "D:/WorkbenchData/cases-root",
  "runtime_root": "D:/WorkbenchData/runtime",
  "port": 8767,
  "performance_sources": ["D:/WorkbenchData/sales"]
}
```

新建空目录后按需要修改路径。**更改路径不会自动搬迁旧数据**：已有数据先在旧配置下导出总数据，再切换到新位置，启动后从 ZIP 恢复。恢复会整体替换新位置中的当前数据，先核对预览内容。

更改配置后停止并重新启动服务。临时换端口也可运行：

```powershell
.\.venv\Scripts\python.exe server.py --port 8768
```

此时打开 `http://127.0.0.1:8768`。已有同一数据目录服务时不要再开第二个实例；先关闭原实例。

## 5. 数据究竟存在哪里

| 资料 | 位置 |
| --- | --- |
| 正式案例及版本事件 | `skill_root/cases` |
| 评论原始导入文件 | `runtime_root/reviews/sources` |
| 评论派生检索库与人工整理状态 | `runtime_root/reviews` |
| 方向、创作、AI 协作、销售与制作资料 | `runtime_root` 下对应目录 |
| 中文阅读目录 | `runtime_root/library` |
| 本机个性化配置 | 项目中的 `config.local.json` |
| 登录、服务密钥和第三方客户端授权 | 对应本机客户端或用户环境配置 |

默认案例根目录是项目里的 `.local/case-library`，正式案例位于其 `cases` 子目录；默认 `runtime_root` 是与其并列的 `.local/runtime`。实际完整路径以「设置 → 本地文件」为准。不要把中文阅读目录当作全部业务数据，也不要把源码仓库当作数据备份。

如果准备把文件提交到自己的仓库，先运行 `git status --short` 看待提交范围；原始评论、销售表、业务截图、备份包、`config.local.json` 和授权文件不应加入公开提交。

## 6. 可选功能：按需配置

### AI 写稿、审稿与复盘

工作台调用本机 Codex 或 Claude 程序，复用各自登录与可用额度。先让对应客户端在电脑上完成自己的安装和授权，再打开「设置 → 模型与连接」。

- Codex：在「AI 协作」点击「重新检查」。找不到程序时，可通过用户环境变量 `CODEX_EXECUTABLE` 指定本机可执行程序的完整路径。
- Claude：点击「连接 Claude 订阅」并完成浏览器授权；页面会检查结果。如需指定程序路径，可设置 `CLAUDE_EXECUTABLE`。
- 在「全局默认模型」中刷新列表、选择可用模型与思考强度，点击「保存全局默认」。可用模型取决于自己的客户端与账号。

**客户端连接与技能资料是两项准备。** 本仓库提供应用和案例存储脚本，不包含作者完整的个人写稿、审稿、案例分析或达芬奇剪辑技能。选择某项技能后，工作台会检查其 `SKILL.md` 及所需参考文件；缺失时会报错，不会自动补齐。

原有创作技能的目录关系为：

```text
自己的技能主目录/
  product-video-script-review/    ← config.local.json 的 skill_root
    SKILL.md
    references/...
    sources/video-cases/case_template.md
    cases/...
  product-video-script-writing/
  product-video-script-audit/
  product-video-case-analysis/
  product-video-media-production/
```

这些名称是现有代码识别的技能标识。只有自己已有兼容资料时才按此配置；不能只创建同名空文件夹就认为 AI 工作流已就绪。基础案例管理与评论整理可先独立使用。

### TikTok 公开指标与评论推送

该入口需要另外安装兼容的 **TK 看板** 浏览器插件，本仓库不含插件安装包。

在工作台「设置」找到「TK 看板插件」，复制 **工作台地址** 与 **连接码**，在插件设置的「案例工作台」中填写。在插件侧读取 TikTok 页面的评论或公开指标后，再执行推送。详细评论流程见 [用户声音教程](用户声音保姆级教程.md)。连接码保存在本机，不要放进公开截图或 Issue。

### 视频抽帧与音频转换

需要本机安装 `ffmpeg` 和 `ffprobe`，并使工作台进程可在 PATH 中找到。安装后重新打开 PowerShell，检查：

```powershell
ffmpeg -version
ffprobe -version
```

两项都能显示版本后，再启动工作台。部分原片下载还可选择安装 `yt-dlp`；成品转写检查使用 `faster-whisper`，首次运行会准备其模型。需要时在同一环境安装：

```powershell
.\.venv\Scripts\python.exe -m pip install yt-dlp faster-whisper
```

销售截图 OCR 使用 `rapidocr-onnxruntime`，也是独立可选依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install rapidocr-onnxruntime
```

没有这些额外组件时，相应媒体任务会提示缺少依赖；无需为了浏览评论提前安装。

### ElevenLabs 配音

配音需要自己的 ElevenLabs 账号、可用额度、声音 ID 与完整 API 密钥。把密钥设置为 **当前用户环境变量** `ELEVENLABS_API_KEY`；不要把密钥写入源码或提交到仓库。

不熟悉命令行时：开始菜单搜索「编辑账户的环境变量」→「用户变量」→「新建」，变量名填 `ELEVENLABS_API_KEY`，变量值填自己的完整密钥。完成后在制作流程中配置声音并检查连接。密钥具体权限和可用声音由自己的 ElevenLabs 账号决定。

### DaVinci Resolve 剪辑

需要安装 DaVinci Resolve Studio，打开目标项目，在「偏好设置 → 系统 → 常规」把外部脚本使用设为「本地」。工作台使用 Resolve 自带的脚本组件，不通过 pip 安装一个同名包代替。

非默认安装位置可使用：

- `RESOLVE_SCRIPT_API`：包含 `Modules/DaVinciResolveScript.py` 的脚本 API 目录。
- `RESOLVE_SCRIPT_LIB`：`fusionscript.dll` 的完整路径。
- `RESOLVE_MCP`：用于 AI 剪辑的 `ResolveMCP.exe` 完整路径。

基础时间线操作与 AI 剪辑所需能力不同；AI 剪辑还要求可用的客户端、MCP 与兼容的个人剪辑技能。工作台会核对当前打开项目，不会自动切换到另一个项目。

### AI 图文与主体保护

当前图生图流程接入 **Cockpit 本机 API**。需自己配置可用的 Cockpit、账户、访问密钥和符合代码约定的请求参数文件；仓库不含作者的本机网关、授权和已验证参数文件。

在 `config.local.json` 中通过 `image_generation.parameters_file` 指向自己的参数文件，必要时设置 `image_generation.auth_config`。也支持由 `COCKPIT_API_KEY` 提供本机接口密钥。参数文件需符合 `cockpit_image_bridge.py` 的本机接口结构；不是任意服务的 URL/API key 就能直接替换。

主体保护还使用 Node 与 Sharp 图像组件，当前实现从 Codex 的本机运行组件位置查找。普通安装 Node.js 并不能单独满足这一流程；组件不可用时按页面提示处理，不要把缺失组件当作图片已生成成功。手工导入已有成品仍可作为对应制作流程的接续方式。

## 7. 备份与恢复

1. 打开「设置 → 数据与备份」。
2. 在「导出总数据」点击「导出全部数据」，等 ZIP 下载完成。
3. 将 ZIP 保存到项目目录之外，最好再留一份到其他磁盘。
4. 需要恢复时在「从文件恢复」选择 ZIP，先阅读包内容与时间预览。
5. 确认目标工作台无误后，再勾选确认并执行恢复。恢复会整体替换当前全部产品数据。

也可在同一区域设置自动备份目录、间隔与保留份数。AI、配音、剪辑或图文任务还在运行时，先等任务结束再进行总数据操作。

第三方账号授权、环境变量和本机个性化配置需要分别维护。旧的启动增量备份与完整总数据备份用途不同；迁移电脑时优先使用完整 ZIP。

## 8. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| `py` / `git` 无法识别 | 安装对应软件后重新打开 PowerShell；用 `py -3.12 --version` 核对 |
| 提示找不到 `server.py` | 当前目录不对；进入解压或克隆后的项目根目录 |
| 缺少 `PIL`、`cv2`、`numpy` 或 `openpyxl` | 用 `.venv` 中的 Python 重新运行 `-m pip install -r requirements.txt` |
| 找不到 `case_store` 等模块 | 检查仓库中的 `scripts/` 是否下载完整；不要只复制 `server.py` |
| JSON 读取报错 | 检查 `config.local.json` 是否为有效 JSON：双引号、无注释、最后一项后无逗号；Windows 路径用 `/` |
| 端口占用或同一数据目录已有实例 | 先关闭旧服务；确认没有其他实例后再启动，或为独立数据目录选其他端口 |
| 提示案例库与运行目录不能相同或嵌套 | 将 `skill_root` 和 `runtime_root` 设置为并列的独立目录，例如 `.local/case-library` 与 `.local/runtime`；已有数据先备份再迁移 |
| 浏览器连接被拒绝 | 看启动终端是否报错；服务必须保持运行；地址端口与终端显示一致 |
| 页面正常但列表为空 | 新安装没有业务数据；导入自己的资料，并检查顶部产品与筛选条件 |
| 切换配置后旧数据不见了 | 可能已指向新目录；旧文件不会随改路径移动，切回旧配置核对并先做备份 |
| AI 不可用或技能文件缺失 | 分别检查客户端登录与技能资料；查看「设置 → 模型与连接」和具体错误 |
| 图文主体保护组件不可用 | 当前流程依赖 Codex 本机 Node/Sharp 组件；基础评论功能不受此项限制 |
| 启动后看不到改动 | Python 后端改动需要重启服务；浏览器可按 `Ctrl+F5` 重新加载 |

手动运行 `server.py` 时，优先看当前终端的错误。使用 Windows 桌面启动器时，可检查项目目录中的 `server.log`、`launcher-error.log`；分享日志前先去掉个人路径、业务内容和授权信息。

## 9. 更新代码

先在界面导出总数据备份，停止服务，然后在项目目录运行：

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

若 Git 提示本地改动冲突，先保留自己的改动再处理，不要用强制覆盖命令解决。`config.local.json` 与本地数据不应提交到公开仓库。

## 开发验证

基础后端测试示例：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_review_store.py -v
```

浏览器测试使用 Playwright，现有测试通过 `channel="chrome"` 启动本机 Google Chrome。先安装 Chrome，再安装 Python 测试依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install playwright
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_noise_shell_ui.py -v
```

媒体测试还可能调用 `ffmpeg`；Node 测试与部署工具有各自依赖。完整测试集合包含真实功能适配和浏览器检查，按变更范围选择；不要把一次基础测试通过当作所有外部服务都已经连接。
