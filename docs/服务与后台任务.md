# 服务与后台任务

Windows 工作台现在由两个独立进程组成：浏览器连接固定端口的网页服务；后台任务引擎持有数据、AI 调用、剪辑、配音、预览及上传工作。网页服务通过本机私有接口读取数据和提交操作。

## 日常重启

更新横幅显示「重启网页服务」时，可以立即重启。浏览器稍后自动刷新，任务引擎进程保持不变，正在运行的任务继续执行和保存结果。双击桌面快捷方式也只更换网页服务。

任务引擎的程序有更新时，页面单独提示「任务引擎将在空闲后更新」。当前任务使用原版本完成；所有任务、完成后的收稿整理以及保存操作都结束后，引擎自动备份并更新。更新引擎的短暂连接间隙可稍后重试。只重启网页服务不复制正在写入的业务数据。

首次从原来的单进程结构切换，需要先等待旧任务完成。运行中的线程和模型会话无法迁移，新结构不会为此强行停止旧任务。旧结构仍保留原重启保护。

## 配置与恢复

`config.json` 的 `task_host_enabled: true` 启用 Windows 启动器的新结构。直接运行 `server.py` 和现有 Mac 部署入口保留原模式。代码更新后依然使用项目规定的启动器重启，不直接结束 Python 进程。

网页服务使用原来的固定端口；任务引擎仅监听随机本机端口，连接登记在运行目录 `service/task-host.json`。登记含本机控制凭据，不作为业务资料导出或恢复，也不随备份迁移。新旧引擎不能同时写入同一套业务数据。

若后台引擎已退出，网页会提示暂未连接；双击桌面工作台快捷方式会检查并恢复引擎。若引擎仍持有数据但连接异常，启动器会保留它并报告原因，不另开第二个数据写入进程。引擎意外退出后，尚未完成的任务仍按原有中断与结果恢复规则处理，不能承诺断电或进程崩溃后无损续接。

日志分别在 `gateway.log`（网页转发）、`server.log`（任务引擎）和 `launcher-error.log`（启动或更新失败）。
