# 用户声音：从导入评论到找到下一条内容选题

这份教程适合第一次使用工作台的人。跟着做，可以完成一条完整链路：把评论放进来，查清评论在说什么，挑出值得回应的问题，带着原文写稿，再把发布结果变成下一次能用的经验。

这里的「用户声音」指**用户评论、商品评价和社区讨论**。配音、声音克隆在制作流程里操作，不在本模块。

教程按本仓库当前界面编写。所有 DEMO 评论、账号、链接和结论都是虚构练习材料，不代表真实消费者反馈。

## 先选一条适合你的路线

| 你的情况 | 从哪里开始 |
|---|---|
| 刚下载项目，还打不开工作台 | 先按 [README](../README.md) 安装、启动，再看下面的「第一次打开」 |
| 能打开工作台，评论库是空的 | 先做「十分钟练习：不用采集工具也能跑通」 |
| 已经有评论 JSON 文件 | 看「导入正式评论：本地文件路线」 |
| 已有配套 TK 看板插件 | 看「导入正式评论：插件路线」 |
| 已经能看到评论，想找到可写选题 | 从「读懂一张评论卡」继续 |

第一次练习不需要 API Key，不需要登录 AI，也不需要购买采集服务。搜索、标签和选题机会由本地规则处理；真正提交 AI 写稿任务时，才需要配置相应服务与技能。

## 1. 第一次打开：先确认你正在看哪个产品

1. 启动工作台，浏览器打开 `http://127.0.0.1:8767`。如果你改过端口，使用自己的地址。
2. 在左侧栏上方找到「当前产品」。侧栏收起时，先把鼠标移到左侧导航区域展开。
3. 先选择「全部产品」。
4. 点击左侧「用户声音」。页面顶部有「评论」「选题机会」两个视图。
5. 第一次没有评论时，出现空列表是正常情况，继续下一节。

**产品选择会影响评论、摘录篮和选题范围。**「全部产品」适合检查导入与归属；准备写稿时，要切回一个具体产品。

## 2. 十分钟练习：不用采集工具也能跑通

这一步只建立一个名为 `DEMO` 的练习产品。练习评论和实际业务数据分开理解，不拿练习数据做产品判断。

### 第一步：找到评论文件应该放在哪里

全新安装的默认运行资料目录是项目下的 `.local/runtime`。在项目文件夹里，按下面的层级新建文件夹：

```text
case-workbench/
└─ .local/
   └─ runtime/
      └─ reviews/
         └─ sources/
            └─ tiktok_video/
               └─ demo.json
```

如果你通过 `config.local.json` 修改了 `runtime_root`，或启动时指定了 `--runtime-root`，应把 `reviews/sources/tiktok_video/` 建在**你实际使用的运行资料目录里**。不要另建一套目录后期待工作台自动找到。

Windows 操作方法：打开项目文件夹，在空白处右键 →「新建」→「文件夹」，逐层建立上面的目录。文件夹名里的下划线必须保留。

### 第二步：保存三条虚构评论

打开记事本，把以下内容完整复制进去。选择「文件 → 另存为」，进入刚才的 `tiktok_video` 文件夹：

- 文件名填 `demo.json`。
- 「保存类型」选「所有文件」。
- 编码选 `UTF-8`。
- 在资源管理器里检查真实文件名是 `demo.json`，没有多出 `.txt`。

```json
[
  {
    "cid": "8000000000000000001",
    "product": "DEMO",
    "text": "Does the clamp hold a small blade without wobbling?",
    "nickname": "Demo Reader A",
    "uniqueId": "demo_reader_a",
    "createTimeISO": "2026-10-26T09:00:00Z",
    "diggCount": 12,
    "videoWebUrl": "https://example.invalid/@demo/video/8000000000000000100"
  },
  {
    "cid": "8000000000000000002",
    "product": "DEMO",
    "text": "The clamp feels unstable. I want to see the base while you sharpen.",
    "nickname": "Demo Reader B",
    "uniqueId": "demo_reader_b",
    "createTimeISO": "2026-10-26T09:05:00Z",
    "diggCount": 8,
    "videoWebUrl": "https://example.invalid/@demo/video/8000000000000000100"
  },
  {
    "cid": "8000000000000000003",
    "product": "DEMO",
    "text": "Where can I buy replacement stones?",
    "nickname": "Demo Reader C",
    "uniqueId": "demo_reader_c",
    "createTimeISO": "2026-10-26T09:10:00Z",
    "diggCount": 3,
    "videoWebUrl": "https://example.invalid/@demo/video/8000000000000000100"
  }
]
```

`example.invalid` 是练习用的无效域名，点击「打开原帖」不能打开真实视频，这是预期行为。正式文件应保留真实来源链接。上面的日期只是虚构评论的发布日期；「近 14 天新增」按你首次把评论导入工作台的日期计算。

### 第三步：在界面中重新同步

1. 回到「用户声音 → 评论」，确认当前产品还是「全部产品」。
2. 点击右上方「重新同步」。
3. 等到页面提示已重新读取文件、共导入评论。全新空库应导入 3 条；已有其他文件时，总数会更多。
4. 打开左侧「当前产品」，选择新出现的 `DEMO`。如果下拉列表还没更新，刷新页面再选。
5. 如果列表里没看到三条评论，先点已生效筛选旁的「清除全部」，并清空搜索框。

**成功标志：**你能看到 Demo Reader A、B、C 的评论；点击「没人回复的提问」后，能找到提问类评论；搜索 `clamp` 能找到前两条。

### 第四步：做一次摘录与选题练习

1. 在第一条评论上点「摘录」，按钮变成「已摘录」。
2. 点页面右上方「摘录篮」。
3. 在这条评论的「写稿备注」里填：`练习：观众担心短刀夹不稳。只提出疑问，待真实装夹画面验证。`
4. 点击备注输入框外的空白位置，等待备注保存。没有「未保存」提示后再继续。
5. 关闭摘录篮，点页面顶部「选题机会」。
6. 你会看到与夹具、小刀或配件有关的主题。同一条评论可能出现在多个相关主题里，不代表多了几个独立用户。
7. 展开主题中的「全文与来源」，对照原文，确认标题没有改变评论的意思。

到这里，已经跑通了「文件 → 评论库 → 检索 → 摘录 → 选题」。AI 尚未配置也可以完成以上步骤。

练习结束后，如果不想让 DEMO 继续出现在评论库，可以把 `demo.json` 移到 `sources` 以外的练习备份文件夹，再点「重新同步」。只移出摘录篮不会删除评论来源；已有摘录和主题关联也应另外核对。

## 3. 导入正式评论：本地文件路线

### 支持哪些来源

本模块读取的是**已经取得的 JSON 数据集**。页面上的「重新同步」会重新读取本地文件，不会自己打开 TikTok、亚马逊或其他网站抓评论。当前评论页面也没有上传 Excel、粘贴整段文字或上传 JSON 的按钮。

将 UTF-8 JSON 文件放在对应平台文件夹里：

| 来源 | `reviews/sources/` 下的文件夹名 | 识别一条记录需要的原始编号 |
|---|---|---|
| TikTok 视频评论 | `tiktok_video` | `cid` |
| 亚马逊评价 | `amazon` | `reviewId` |
| TikTok Shop 商品评价 | `tiktok_shop` | `review_id` |
| Reddit 评论 | `reddit` | `id` 或 `parsedId` |
| Facebook 评论 | `facebook` | `id` 或 `commentId` |

文件可以命名为 `batch-01.json`、`batch-02.json` 等。每个文件最外层必须是 `[` 开始、`]` 结束的列表，列表里面每一项是一条评论。CSV、Excel、网页 HTML 和最外层为 `{ "items": [...] }` 的文件，都不能直接按这条路线导入。

### 产品归属一定要填清楚

- **TikTok 视频评论 JSON：**每一条写明 `"product": "你的产品名或型号"`。
- **亚马逊、TikTok Shop、Reddit、Facebook JSON：**每一条写明 `"productModel": "你的产品名或型号"`。
- 同一个产品统一使用同一名称，避免一部分写昵称、一部分写型号。
- `sku` 或款式是用户购买的具体选项，不等同于工作台的产品归属。

当前解析器保留了原项目的默认产品 `202H`。漏填产品字段时，部分来源会落到这个默认产品，并不会自动识别成你的商品。开源后用于其他品类时，请显式填写实际产品，先用两三条样本验证归属。

### 每个平台的字段对照

不同采集工具导出的字段名可能不同。「都是 JSON」不表示能直接导入。下面是当前代码读取的主要字段，工具输出名称不同时需要先转换。

| 来源 | 正文、时间和身份等字段 |
|---|---|
| TikTok 视频评论 | `text` 正文；`nickname` / `authorName` 昵称；`uniqueId` 账号；`createTimeISO` 时间；`diggCount` 点赞；`videoWebUrl` / `submittedVideoUrl` 视频链接；`repliesToId` 被回复的原评论编号；`videoAuthor` 视频作者账号 |
| 亚马逊 | `reviewDescription` 正文；`reviewTitle` 标题；`userName` 昵称；`date` 时间；`ratingScore` 星级；`reviewReaction` 有帮助数；`isVerified` 验证购买；`isAmazonVine` 激励评价；`reviewUrl` 来源；`variant` 款式 |
| TikTok Shop | `review_text` 正文；`reviewer_name` 昵称；`review_time` 时间；`review_rating` 星级；`is_verified_purchase` 验证购买；`is_incentivized_review` 激励评价；`sku_specification` 款式；`product_id` 平台商品编号 |
| Reddit | `body` 正文；`username` 账号；`createdAt` 时间；`url` 链接；`communityName` / `parsedCommunityName` 社区名；如有 `dataType`，应为 `comment` |
| Facebook | `text` 正文；`profileName` / `author.name` 名称；`date` 时间；`likesCount` 点赞；`inputUrl` 原帖；`commentUrl` 评论链接；`postTitle` 原帖标题 |

布尔字段请用 JSON 的 `true` / `false`，不要用字符串 `"false"` 代替。否则某些解析器可能把非空字符串理解为「是」。

### 正式导入的操作顺序

1. 先保留一份原始导出文件。
2. 抽查几条，确认编号、正文、时间、产品和来源字段存在且含义正确。
3. 把需要导入的文件放进对应平台目录。
4. 在工作台选「全部产品 → 用户声音 → 重新同步」。
5. 阅读同步提示。有「未导入」「找不到文件夹」时，先处理具体文件问题。
6. 选择目标产品，清掉旧筛选，再核对一条你认识的评论。
7. 点击「数据来源说明」，查看各来源的数量、日期和注意事项。

平台内相同原始编号用于去重，所以同一批文件重复同步不会无限叠加条数。保留原始编号，不要每次重新随机编号。**原始来源文件是重建评论库的依据**；移走正式来源后再同步，会改变库中可用的评论，先备份再整理。

## 4. 导入正式评论：配套 TK 看板插件路线

这条路线需要另外安装并配置与工作台兼容的 TK 看板插件。**本仓库不等于浏览器采集插件，也不包含所有外部采集服务。**没有插件时，使用上一节的本地文件路线即可。

已有配套插件时，按以下顺序做：

1. 打开要研究的 TikTok 视频，确认视频本身已经进入工作台可识别的视频记录。
2. 在工作台核对这条视频属于哪个产品。
3. 在平台页面展开评论，按需要继续滚动并展开回复，让插件实际读取到正文。
4. 使用插件的视频推送能力，或在插件的评论研究页面点击「存到用户声音」。插件界面与授权方式由插件本身管理。
5. 回工作台，选「全部产品 → 用户声音」，检查评论是否出现，再切到目标产品。
6. 如插件提示抓取不完整，回原评论区继续加载，重新读取、再推送；保存成功只表示收到当前这一批。

工作台按原评论 ID 合并，保留正文、昵称或账号、点赞、时间和已有回复关系。后续只推送一部分评论，不会因此删除此前已收录的其他评论；新一批没提供昵称，也不会用空值覆盖已知昵称。

如果视频已存在但尚未归属产品，评论会显示「未关联产品」，先在「全部产品」检查。它们不会凭当前侧栏选项自动变成这个产品的评论。应先修正视频归属，再重新读取或推送核对。对工作台完全未知的视频，评论推送可能被忽略，应先导入视频。

**不要把三个数量混在一起：**

| 数字 | 它表示什么 |
|---|---|
| 平台页面的评论总数 | 平台展示的公开指标 |
| 插件当前读到的条数 | 当前缓存中实际取得的评论 |
| 工作台已收录条数 | 已导入并保留的评论正文，可能包含历史批次 |

这三个数字可以不同。页面显示 1,000 条评论，不表示工作台已经有 1,000 条正文；「库里没有回复」也不表示平台原帖无人回复。

## 5. 读懂一张评论卡

先读正文，再看来源与身份，最后才用标签。建议每条按这个顺序核对：

1. **谁说的：**顶部昵称与账号来自原始来源。显示「评论者未记录」表示来源没有提供名称，不表示这是匿名平台。
2. **在哪说的：**TikTok 视频评论、Shop 商品评价、亚马逊评价和社区讨论的语境不同。
3. **什么身份：**看下面的身份标签。
4. **原文完整吗：**长评论点「展开全文」。不要只凭搜索摘要下结论。
5. **有没有上下文：**TikTok 回复可点「看上下文」或「展开对话」，检查它在回答谁。这里展示的是库内已取得的对话。
6. **能否回到来源：**点卡片右下的「… → 打开原帖」。来源没提供链接时，不会凭空生成原帖。

| 身份标签 | 怎么使用 |
|---|---|
| 已验证买家 | 来源标记为已验证购买；体验描述仍是评论者自己的说法 |
| 试用/有激励买家 | 可能免费试用或存在激励，需要保留这层背景 |
| 未验证购买者 | 没有验证购买标记，不宜自行升级为已验证买家 |
| 观众 | 看过视频的人，不一定买过或使用过商品 |
| 社区讨论者 | 社区讨论或转述，不能直接当作产品测试记录 |
| 品牌或达人账号 | 品牌或创作者自己的回复，默认隐藏；不是独立用户意见 |

「买家亲历」等**内容性质标签**是规则对文字的判断，和平台的**购买验证身份**是两回事。正文写「我用过」不会自动产生已验证购买凭证。

本模块默认隐藏品牌/达人回复、只打星没有正文的评价、被判定没有提到产品的评论。查看这些内容时，打开「筛选」，在「默认隐藏的内容」勾选对应选项。

当前自动标签、中文搜索词映射和部分相关性判断主要围绕英文磨刀器评论设计。换品类、换语言时，应先抽查规则；例如 Reddit 的相关性规则仍偏原项目产品。不能把自动隐藏理解成「这条评论没有价值」。

## 6. 用搜索和筛选找到真正值得读的评论

### 最省力的阅读顺序

1. 点「具体缺陷」，先找能影响购买决策的限制。
2. 点掉该筛选，再点「没人回复的提问」，找可以用真实演示回答的问题。
3. 点掉该筛选，再点「低星评价」，看不满意的具体原因。
4. 最后看「近 14 天新增」，找最近才进入你库里的新表达。

快捷按钮可以叠加条件。结果忽然为 0 时，先看搜索框下方已有的筛选标签，逐个点掉，或点「清除全部」。

### 搜索怎么用

- 优先搜评论中的英文原词，例如 `clamp`、`wobble`、`replacement`。
- 也可以试中文，例如「夹具」「晃动」「价格」。已配置词典的中文会扩展为英文词，页面下方会说明扩展了什么。
- 不是所有中文都会翻译。显示「没有对应的英文词」时，改用英文原词或主题标签。
- 一次先搜一个概念。多个词会继续收窄条件，结果太少就减掉一个词。
- 初次加载分批显示，继续向下滚动或点「再显示…条」查看后续。

### 「筛选」里还有什么

可以按星级、评论者身份、语言、回复情况、视频、款式，以及性质、主题、竞品标签筛选。只在已有相关数据时才出现视频或款式选项。

「没人回复的提问」限定 TikTok 视频评论，表示**已收录的对话里没有回复**。其他来源的评价不会因为没有回复字段就混进这个快捷筛选。

「近 14 天新增」按**首次入库时间**计算。一条去年的评论今天首次导入，也可能显示为新增；它不能用来判断平台最近 14 天流行什么。

默认按点赞/有帮助数排序。需要看新问题时，改成「最新」；排查负面体验时，可改成「星级从低到高」。没有星级的平台不适合用「低星评价」找问题。

### 两种复制的区别

- 一条评论上的「复制引用」：复制这一条的原文、来源身份等信息。
- 页头「复制当前结果」：复制当前筛选下**已经加载的评论**。例如结果共 230 条、当前加载 50 条，复制的是这 50 条；复制内容会说明数量。

## 7. 标签打错了：改标签，而不是改评论原文

1. 找到那条评论，点「… → 改标签」。
2. 在「性质」「主题」「竞品」中点击需要添加或去掉的标签。
3. 每点一次都会保存，手动改过的标签会用虚线样式提示。
4. 关闭编辑区域，重新筛选确认结果。
5. 页面有「复制纠错清单」时，可以复制手动改过的记录，供后续调整规则。

手动标签会在重新同步后保留。它们帮助你纠正分类，不会改写评论者原文，也不会把评论说法变成已验证事实。

例如一句「夹具能夹住小刀吗？」应先理解成提问，不能因为出现了「小刀」就直接写成「已经证明适配所有小刀」。

## 8. 摘录篮：把要用的证据带进写稿

摘录篮类似一个带来源的素材夹。它还可以收案例表达和视频钩子，所以看见其他类型素材是正常的。

1. 在值得保留的评论上点「摘录」。
2. 点页头或侧栏的「摘录篮」。宽屏时可能靠右停靠，窄屏时以弹窗显示。
3. 确认当前产品，只勾选本次要用的材料。
4. 给每条填写「写稿备注」。建议包含：它说明什么、可以怎么用、还缺什么证据。
5. 点击输入框外保存。出现冲突或「未保存」提示时，先核对，再继续。
6. 需要自己整理时点「复制所选」；要在工作台调用 AI 时点「带入写稿」。

可直接套用的备注结构：

```text
用途：观众担心装夹是否麻烦，适合作为开头问题。
想拍：完整装夹过程和底座近景，不跳过关键操作。
边界：评论者是观众，不作为买家实测；暂时没有耗时数据。
```

「移出摘录篮」只是从素材夹移出，不会删除评论原文；已有的主题关联仍可能保留。「清空当前产品」也只是清空这个产品的摘录素材，先核对产品再操作。

提交 AI 任务时，系统会固定本次选择的素材。之后再改篮子或备注，不会回头改变已提交任务。想让新备注生效，应在提交前保存，或在后续任务中重新带入。

## 9. 关联主题：把评论和卖点、顾虑连起来

这里有两个容易混淆的动作：

| 动作 | 用来回答什么 |
|---|---|
| 改标签 | 这条评论在谈夹具、价格，还是配送？它是提问还是缺陷？ |
| 关联主题 | 这条评论具体对应我的哪个产品卖点，或哪条方向中的顾虑？ |

### 操作方法

1. 在评论上点「… → 关联主题」，也可以在摘录篮点「关联卖点或顾虑」。
2. 在「用途」选择「产品卖点」或「方向顾虑」。
3. 在「关联到」选择当前产品已有的卖点或方向。
4. 在「备注」说明关联原因和使用边界。
5. 点「保存主题关联」。

若显示「当前产品暂无可关联条目」，先关闭窗口，到左侧「卖点与方向」为这个产品建立卖点或方向，再回来关联。没有真实资料支撑的卖点应保持待核候选，不能为让列表有内容就编一个事实。

例如把「能不能夹住短刀？」关联为某方向的顾虑，备注写「需要补短刀装夹演示」。这表示该方向应该回应这个问题，不表示产品适配能力已经得到证明。

关联错了可以重新打开「关联主题」，在「已有关联」里删除。把评论移出摘录篮不会同时解除关联。

## 10. 选题机会：把一组评论变成可验证的内容问题

选择一个具体产品，再点「用户声音 → 选题机会」。如果提示「先选择一个产品」，回侧栏选择，不能跨产品混算。

每张主题卡主要看四部分：

1. **主题与样本：**有哪些不同原文，来自哪些来源。
2. **原文证据：**展开「全文与来源」，检查评论实际在说什么；卡片只挑部分原文展示。
3. **已有覆盖：**关联到了哪些卖点和方向，有多少脚本、多少已发布，是否已有计划。
4. **下一步：**「查看同主题评论」「关联这条评论」或「带证据写稿」。

当前排序优先考虑近 14 天首次入库的不同原文数量，再看关联方向是否已有发布、手动标注、不同原文数量与来源数量。点「来源与排序口径」可核对。它是帮助你安排阅读顺序，不是预测爆款，也不调用 AI 替你下市场结论。

### 读数字时记住三个边界

- 相同原文会合并，跨来源数量可以重叠，不能直接相加成独立消费者人数。
- 一条评论可涉及多个主题，各主题的条数不能相加当作总评论数。
- 「已有发布脚本」表示有人做过这个方向，不等于已经验证有效；评论频次也不等于市场占比。

「待整理证据池」表示评论尚未形成具体主题。先核对全文、修正标签或关联用途，不能把它当作系统已经发现的成熟选题。

### 点「带证据写稿」后怎么做

1. 若主题已有对应方向，按需在「带入方向」里选一个；也可以保持「空白写稿，不指定方向」。
2. 点「带证据写稿」。
3. 在「开始写稿」窗口核对「本次方向」和「这次希望怎么做？」。
4. 自动填入的要求会附评论证据、样本说明和未经核实的边界。补充你的真实产品资料、目标受众、准备使用的实拍证据。
5. 核对是否携带摘录篮；不要把与本次无关的材料一起带入。
6. 查看「技能与服务」状态，确认 AI 服务、模型和所需技能可用。
7. 点「开始协作」，在「内容创作」查看进度与候选。
8. 逐句核对事实后再采纳。生成稿里出现未经提供的测试数据、用户身份或使用经历时，要修改或要求重写。

如果弹窗里保留了另一条未完成的写稿请求，系统会保留原输入，不自动覆盖成当前主题。先完成或关闭原请求，再从需要的入口发起。

### 另一种入口：「顺着这条写稿」

在某条评论的「…」菜单里选择「顺着这条写稿」，适合以观众立场为开头，再写创作者自己的态度和使用动机。

窗口中会留出「我的真话」。优先填写自己真实认可的感受；留空时，AI 只能反推态度或感受，并应标注 `【AI反推】`。核对并改成自己的真实表达后再使用。不能把 AI 反推写成「我用了半年」或「提升三倍」这类具体经历与效果。

## 11. 一个完整示例：从问题到下一轮经验

以下仍是虚构练习，描述的是工作方法。没有完成拍摄和发布时，不要把后续结果登记成真实表现。

```mermaid
flowchart LR
    A[导入原评论] --> B[核对来源与标签]
    B --> C[摘录并记使用边界]
    C --> D[关联卖点或方向顾虑]
    D --> E[带证据写稿]
    E --> F[实拍核对与发布登记]
    F --> G[观察数据并保存复盘]
    G --> H[记一条经验供下次参考]
```

**起点：**你看到 DEMO 评论「Does the clamp hold a small blade without wobbling?」

1. **识别问题。**它是视频观众的提问，未证明他买过产品，也未证明产品会晃。
2. **保留证据。**点「摘录」，备注「短刀装夹和晃动是待回应问题，需要真实镜头」。
3. **关联用途。**若已有适合的方向，把它关联为「方向顾虑」。没有方向时，先在「卖点与方向」建立基于真实产品资料的方向。
4. **形成选题。**选题写成「把短刀装夹过程完整拍出来，让观众看清限制」，不要直接写「所有短刀都能稳稳夹住」。
5. **发起写稿。**从主题卡点「带证据写稿」，追加实际刀型、可拍画面、已知限制；不确定的地方要求留待核对。
6. **检查稿件。**确认没有把观众提问改成买家证言，没有编造测试次数和效果。审核后再采纳并进入制作。
7. **完成制作与发布登记。**在「内容创作」的对应内容里继续制作，发布后绑定实际视频与采用稿件版本，填写实际日期。
8. **观察与复盘。**到「工作概览 → 待复盘」查看。登记发布的视频先进入观察，满 14 天且首 14 天播放、订单覆盖完整后进入待复盘；数据不全时会提示缺口，也可以先保存带限制的结论。
9. **保存结论。**打开「开始复盘」或「核对结论」，写清你看到了什么、还不能判断什么，选择人工确认的参考价值，点「保存复盘」。单纯有播放或成交，不自动等于选题被验证。
10. **沉淀经验。**对已经确认保存的复盘点「记一条经验」，选成功做法或失败教训，填写「下次记住什么」，必要时补适用条件与证据，再保存。

可写的经验形式是「装夹类问题的回应保留底座和手部连续镜头，适用范围以本次实拍刀型为限」。**只有当实际复盘支持这条做法时才保存**；一条提问本身还不能证明这种拍法有效。

复盘经验的入口在「工作概览 → 待复盘 → 经验与更多 → 复盘经验」。评论主题与选题在「用户声音」，发布后的结论与经验在复盘流程中，两者通过产品、方向和内容记录衔接。

后续可在经验库搜索、编辑、停用或恢复。写稿、审稿会按同产品及匹配方向参考可用经验；来源复盘改判后，相关经验会暂停带入新任务。「无参考价值」记录及其经验仍能检索，但不会自动带入新任务。经验是下一轮参考，不是把评论升格成产品事实。

## 12. 常见问题：按顺序排查

| 现象 | 先做什么 |
|---|---|
| 页面没有任何评论 | 选「全部产品」，清空搜索与筛选；检查文件是否放在实际 `runtime_root/reviews/sources/平台名/` 下；点「重新同步」看具体提示 |
| 提示找不到文件夹 | 新建缺少的 `reviews/sources` 和平台目录；仅新建项目根目录的同名文件夹无效 |
| 文件显示「不是数据集导出（应为列表）」 | 检查最外层是不是 `[...]`；从 `{ "items": [...] }` 中取出列表后再导入 |
| 文件已读到，但评论没有导入 | 检查平台目录、编号字段和正文字段；有错误项或缺少编号的记录会跳过；确认真实扩展名不是 `.json.txt` |
| 中文乱码或 JSON 读取失败 | 用 UTF-8 保存；JSON 使用英文双引号，去掉注释和末项多余逗号；保留原始文件再修复 |
| 导入后在当前产品看不到 | 回「全部产品」检查；TikTok 文件看 `product`，其他四类看 `productModel`；插件路线核对视频归属 |
| 明明是别的产品，却跑进 202H | 原始文件漏了产品字段，触发了旧默认值；补实际产品后重新同步 |
| 有昵称但只显示「评论者未记录」 | 检查来源实际字段名是否匹配；旧来源缺名称时，需要重新取得名称再同步/推送 |
| 搜中文搜不到 | 查看搜索映射提示，换评论中的英文词；中文映射不是自动翻译，其他品类需要调整词典 |
| 「低星评价」下 TikTok 视频评论消失 | 视频评论通常没有星级；清掉低星条件，再用提问或主题查 |
| 「没人回复」但原帖明明有回复 | 库里未取得那批回复；在采集端展开回复后重新获取；这项筛选只描述库内情况 |
| 同步总数比默认列表多 | 默认隐藏了品牌回复、无正文或无关内容；先看「数据来源说明」与「筛选」 |
| 评论总数与平台不一致 | 区分公开总数、当前采集条数、历史已收录正文；检查采集是否完整与同 ID 去重 |
| 「近 14 天新增」里有旧评论 | 它按首次入库日算，旧评论今天导入也算新入库 |
| 「复制当前结果」没有复制所有匹配项 | 先继续向下加载，再复制；页头复制只包含已加载结果，复制文本会注明数量 |
| 标签明显不对 | 用「… → 改标签」纠正；换品类时让维护者调整 `review_taxonomy.py` 的规则与中文词典 |
| 选题机会要求先选产品 | 侧栏选具体产品，不能用「全部产品」做主题汇总 |
| 主题关联下拉框为空 | 该产品还没有卖点/方向，或当前产品不对；先到「卖点与方向」建立并核对 |
| 摘录篮里混了多个产品 | 回侧栏选一个产品；核对勾选内容后再带入写稿，不跨产品拼证据 |
| 备注提示冲突、未保存或 409 | 保留自己的文字，重新读取最新资料，核对其他页面的修改后再保存；不要反复盲点 |
| AI 写稿不可用，但评论能看 | 评论检索与主题规则本地运行；检查「设置」及写稿窗「技能与服务」的 AI 登录、桥接与技能配置，按 README 的依赖说明配置 |
| 点选题后弹窗还是旧要求 | 这是保留中的未完成请求；先核对并处理该请求，再开新选题 |
| 提示手动记录文件读不了 | 先备份运行资料，检查 `reviews/state.json` 的错误；不要把这个文件直接删掉重来，它保存手动标签等记录 |

## 13. 备份：保住原始评论，也保住你做过的整理

常用方法是打开「设置 → 数据与备份」导出总数据 ZIP。它覆盖评论、方向、创作、销量等业务资料，适合迁移或更新前使用。

如果手工备份，应理解各部分的作用：

| 位置（相对实际运行资料目录） | 作用 |
|---|---|
| `reviews/sources/` | 原始评论来源，重新同步时用于重建评论库 |
| `reviews/state.json` | 首次入库日期、手动标签等人工整理记录 |
| `reviews/reviews.sqlite` | 评论检索数据库，可由来源与状态重建；不能代替原始资料与人工记录备份 |
| `creation/`、`directions/` 及其他业务目录 | 摘录、关联、方向、任务与复盘链路相关资料，应按整体数据备份处理 |

不要只备份数据库、只拷贝网页代码，或者以为推送 Git 就备份了评论。开源仓库只发布程序与虚构示例，自己的评论、销售资料、账号授权和运行记录按本地备份流程维护。

恢复前先在「设置 → 数据与备份」查看备份内容与时间，再执行恢复；不要在运行中的系统里随意替换数据库文件。

## 14. 第一次使用的完成标准

完成以下检查，就可以把练习换成正式数据：

- [ ] 能在「全部产品」同步，在具体产品下找到正确评论。
- [ ] 能解释一条评论的来源、身份、原文与上下文。
- [ ] 能清除筛选，搜到同一条评论，并纠正一个误标签。
- [ ] 能摘录、保存备注，并区分「移出篮子」与「删除来源」。
- [ ] 能把评论关联到具体卖点或方向顾虑。
- [ ] 能从选题主题打开写稿窗，并核对随任务带入的证据。
- [ ] 知道评论是需求与表达线索，商品事实、使用经历与效果需要另外核实。
- [ ] 已完成一次整体数据备份，知道正式评论没有随代码上传到 Git。

操作入口的简版说明见 [使用说明](../使用说明.md)，部署与依赖见 [README](../README.md)。
