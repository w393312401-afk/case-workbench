# 项目地图

想改某个功能，先在这里找到业务线，再看对应文件。新增或删除文件后运行 `python scripts/check_project_map.py`，它会列出地图里漏记或已失效的文件。

## 工作台怎么运转

```text
用户声音 → 内容方向 → 内容创作 → 视频制作 → 发布登记 → 带货数据与复盘
                                                         │
                                  经验和结论回到下一轮写稿 ←┘
```

- 浏览器打开 `static/index.html`，页面通过 `/api/...` 调用本机服务 `server.py`。
- `server.py` 负责接收请求，具体业务交给下面各业务线的文件。
- 真实业务数据保存在项目内，位置见[数据在哪里](#数据在哪里)；数据不纳入源码 Git。
- `desktop_windows.py` 负责在资源管理器中选中文件，以及将资源管理器或达芬奇窗口调到前台。

## 命名规律

| 文件名 | 含义 |
|---|---|
| `xxx_store.py` | 负责读写这条业务线的数据 |
| `workbench_xxx.py` | 接口背后的业务流程 |
| `xxx_bridge.py` | 调用外部程序，如 Claude、Codex、达芬奇 |
| `tests/test_xxx.py` | 后端测试；以 `_ui` 结尾的是浏览器测试 |

**容易混淆：** `review` 有两种意思。`review_store.py`、`review_taxonomy.py`、`review_opportunities.py` 是**用户评论**；`review_policy.py`、`review_followups.py`、`review_experiences.py` 是**视频复盘**。

- **不停任务重启：** Windows 启动器在 `task_host_enabled` 开启时启动独立网页服务 `service_gateway.py`；`server.py --task-host` 持有业务数据及后台任务。网页重启只更换网关进程；引擎更新通过 `launcher_control.py --refresh-task-host-on-idle` 等所有任务及完成回调保存后自动执行。首次迁移要等旧任务结束；连接与恢复见 [服务与后台任务](服务与后台任务.md)。本机控制登记在运行目录 `service/task-host.json`，不进入备份、导入或公开导出。
- **重启端到端验证：** `test_service_restart_e2e` 在临时安装中启动独立宿主和网页进程，通过真实重启接口连续重启并用浏览器核对进度续接；验证请求重试、完整结果、完成回调及通知都不重复。仅模型调用使用可控测试连接，业务任务和落盘走真实流程。
- **加载速度（2026-11-16）：** ① 引擎和网页服务启动时调用 `app_config.py` 的 `keep_full_speed`，让 Windows 不要把这两个没有窗口的进程当后台任务放到能效核降速运行（被降速时每个接口多花约 4 倍 CPU，看起来就是「所有页面都慢」）。② `server.py` 的 `output`：16KB 以上的回答用 gzip 6 级；GET 的 JSON 回答带 `ETag`，页面带着手里那份的标记来问、内容没变就回 304 空包（`Cache-Control` 仍是 `no-store`，浏览器不落盘）；每个回答带 `Server-Timing: total, cpu`，在浏览器网络面板能看到服务端总耗时和其中自己计算的部分，两者差得多说明在等锁或被别的请求挤占。③ 页面这边 `app.js` 的 `requestApi` / `heldAnswers` 只在内存里留最近的回答原文（上限 24MB），304 时用它重建；同时发起的相同读取共用一次请求，各自从原文解析一份。④ 销售列表给每个读取方的副本用 `performance_store.clone_records`（比 deepcopy 快几倍），`ai_tasks.status` 不再为了数排队任务把每条任务整份复制。⑤ 访客快照（部署目录里的快照生成与导出程序，见[完整工作台公网访问](../deployment/完整工作台公网.md)）改成一次读一条、读完歇同样长的时间，并等保存停下 90 秒（最长 10 分钟）才重建，不再在你操作时并发 4 路把引擎占满。测速时别对线上引擎挂调试器：把运行资料不含媒体复制到临时目录，直接调 `Workbench` 的方法计时（构造时把 `threading.Thread.start` 换成空函数，别让后台任务跑起来）。

## 数据在哪里

路径由 `config.json` 和本机的 `config.local.json` 决定，`config.local.json` 优先。本机案例、运行资料和销售原表集中在项目的 `工作台数据/`；个人技能代码仍由桌面 `skill/` 管理。旧数据路径只保留指向项目内的兼容目录链接。

|---|---|---|

**两种备份范围不同：**

- **重启备份**（`launcher_control.py` 的 `BACKUP_SOURCES`）：包含方向、稿件、版本、AI 任务、评论、导航分配、案例资料，以及制作单、发布登记、配音 MP3、销售数据库、证据和剪辑台账。`production`、`library`、`performance`、`evidence` 只留记录：**不含图片、视频和 WAV，也不含缓存和一次性旧库副本。**
  - **保留：** 最新 14 份完整备份，再加最近 14 天每天最新一份。比上一份完整备份明显变少（某一来源的文件数不到一半，或核心目录缩到一成以下）的备份，文件名带 `-thin`，只保留最新 5 份，不占完整备份名额，并记入 `launcher-error.log`。比较基准超过 30 天后自动更新，刻意的大清理不会一直被当成丢失。
  - **恢复：** 先停服务，选最新且不带 `-thin` 的备份，把 `runtime/` 解压到 `runtime_root`，把 `skill/` 解压到 `skill_root`。
- **完整备份**（`data_backup.py`）：包含运行目录的大部分内容和 `图文素材`，只排除缓存、临时文件和登录凭据；媒体只有这里有。在设置页导出，或开启自动备份。备份位置在设置页选择，只能放在 `archive/` 内或项目外；清理时只删自动备份登记过的文件，同目录的恢复包不动。本机（2026-11-15 核对）：位置 `F:\案例工作台备份`，自动备份已关闭，需要时在设置页手动备份或重新开启。
