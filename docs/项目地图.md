# 项目地图

想改某个功能，先在这里找到业务线，再看对应文件。新增或删除文件后运行 `python scripts/check_project_map.py`，它会列出地图里漏记或已失效的文件。

## 工作台怎么运转

```text
用户声音 → 内容方向 → 内容创作 → 视频制作 → 发布登记 → 带货数据与复盘
                                                         │
                                  经验和结论回到下一轮写稿 ←┘
```

- 浏览器打开 `static/index.html`，页面通过 `/api/...` 调用本机服务 `server.py`。
- `server.py` 负责接收请求，具体业务交给下面各业务线的文件。
- 真实业务数据不在代码目录，位置见[数据在哪里](#数据在哪里)。

## 命名规律

| 文件名 | 含义 |
|---|---|
| `xxx_store.py` | 负责读写这条业务线的数据 |
| `workbench_xxx.py` | 接口背后的业务流程 |
| `xxx_bridge.py` | 调用外部程序，如 Claude、Codex、达芬奇 |
| `tests/test_xxx.py` | 后端测试；以 `_ui` 结尾的是浏览器测试 |

**容易混淆：** `review` 有三种意思。`review_store.py`、`review_taxonomy.py`、`review_opportunities.py` 是**用户评论**；`review_policy.py`、`review_followups.py`、`review_experiences.py` 是**视频复盘**；`prepublish_review.py` 是**发布前审查**。

## 数据在哪里

路径由 `config.json` 和本机的 `config.local.json` 决定，`config.local.json` 优先。

| 配置项 | 目录 | 内容 |
|---|---|---|
| `skill_root` | `cases`、`references`、`sources` | 案例记录、参考资料、来源文档 |
| `runtime_root` | `directions` | 卖点与测试方向 |
| | `creation`、`revisions` | 稿件、内容列表与修改版本 |
| | `ai-tasks` | AI 任务与每轮结果 |
| | `reviews`、`evidence` | 用户评论库、证据与产品标注 |
| | `production` | 制作单、配音、发布登记 |
| | `library` | 案例视频与媒体 |
| | `performance` | 销售数据库 |
| | `davinci-ledger` | 剪辑台账 |
| 代码目录 | `archive/data-backups`、`archive/logs` | 重启时的备份和归档日志，别移走 |
| 代码目录 | `图文素材` | 完整备份会读取，别移走 |

**两种备份范围不同：**

- **重启备份**（`launcher_control.py` 的 `BACKUP_SOURCES`）：只包含方向、稿件、版本、AI 任务、评论、导航分配和案例资料，保留最新 14 份。**不含制作单、媒体和销售数据库。**
- **完整备份**（`data_backup.py`）：包含运行目录的大部分内容和 `图文素材`，只排除缓存、临时文件和登录凭据。在设置页导出，或开启自动备份。

## 根目录其他内容

| 位置 | 用途 |
|---|---|
| `tests/` | 全部测试，日常不用看 |
| `docs/` | 安装、教程和历史更新 |
| `使用说明.md` | 面向使用者的完整说明 |
| `reports/` | 审查报告，部分界面测试也会写入截图 |
| `图文成品`、`图文提示词` | 旧图文资料，旧任务和技能还引用这些路径 |
| `deployment/` | 公网站点的构建与部署工具，`site/` 是生成结果 |
| `sources/` | 案例文档模板 |
